**Diagnosis (#1).** Not duplicate data. The MTG and Lorcana importers deliberately emit one catalogue row per physical finish (`lib/apis/lorcast.ts` `normalizeLorcastCard` — nonfoil + foil; `lib/apis/scryfall.ts` — nonfoil/foil/etched), distinguished only by `cards.variant` ('', 'Foil', 'Etched'). The browse tiles (`components/catalogue/CatalogueBrowser.tsx` ~160–181) and `BuyCard` (`components/buylist/BuyCard.tsx` ~83) never render `variant`, so the finish twins look pixel-identical → perceived duplicates. The dead clicks: in Purchasing → Browse, selecting a tile prepends a `BuyCard` below the 360px browse panel with a **silent dedupe on `card.id`** (`app/(app)/buylist/page.tsx` `handleBrowseSelect` ~85) — re-clicking an already-added card is a literal no-op, and no click gives scroll/highlight/toast feedback, so adds below the fold look like nothing happened. Pokémon has one row per card, which is why this only surfaced on Lorcana (MTG is equally affected). POS search results (`components/pos/CardResult.tsx`) also omit `variant` — same confusion waiting on the sell side.

**Diagnosis (#2).** "By Pokémon" (`CatalogueBrowser.tsx:114`) and the placeholder "Type a Pokémon name…" (`:139`) are hardcoded regardless of the game filter. Per-game metadata already lives in `lib/games.ts` (`GAMES`); the filter also has an 'all' state that needs a neutral label. "By Set" is correct for all four games.
